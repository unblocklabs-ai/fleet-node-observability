# Extraction Catalog From `fleet-observability`

Source reviewed:

- `<source fleet-observability checkout>`
- Branch: `main`
- Review date: 2026-06-23

This catalog lists code and functionality that should move or be copied into
this node-side repository, plus related code that should stay in the central
`fleet-observability` repository.

## Split Rule

Move code here when it runs on, installs onto, or configures an individual Mac
mini node.

Keep code central when it runs on Charizard, manages fleet inventory, generates
central observability config, provisions dashboards, validates live central
services, or manages secrets consumed by Alloy/Prometheus.

## Move Or Copy Into This Repo

### Node Host Installers

Source files:

- `scripts/install-node-exporter.sh`
- `scripts/install-off-lan-host-metrics.sh`

Functionality to preserve:

- macOS-only guardrails.
- Homebrew `node_exporter` discovery/install behavior for LAN nodes.
- root LaunchDaemon path for off-LAN nodes.
- user LaunchAgent path for LAN nodes.
- node_exporter textfile collector setup.
- `fleet_node_exporter_textfile_install_info` marker metric.
- Codex usage textfile collector install and scheduling.
- OpenClaw gateway readiness textfile collector install and scheduling.
- macOS thermal pressure textfile collector install and scheduling.
- off-LAN local `node_exporter` binding to `127.0.0.1`.
- off-LAN token-gated proxy on `127.0.0.1:19100`.
- stale listener cleanup before loading off-LAN LaunchDaemons.
- removal of temporary cron lines for old off-LAN host-metrics bootstrapping.
- local metrics verification with `node_cpu_seconds_total`.

Required adaptation:

- Remove direct dependency on private `fleet/nodes.json`.
- Replace embedded Python lookups through `fleetlib.load_inventory()` and
  `node_by_label()` with one of:
  - explicit CLI flags, or
  - a small node-local config file generated by the central repo.
- Do not require a full checkout of central dashboards/configs on each node.
- Keep central OTLP/Alloy configuration out of these installers. They should
  install host-health collectors only.

Likely new interface:

```bash
scripts/install-node-exporter.sh \
  --node-label bill \
  --node-user billjohansson \
  --node-exporter-port 9100 \
  --openclaw-ready-url http://127.0.0.1:18789/readyz \
  --codex-profile default

sudo scripts/install-off-lan-host-metrics.sh \
  --node-label mini_03 \
  --node-user fleet-mini-03 \
  --node-exporter-port 9100 \
  --tunnel-hostname node-exporter-mini-03.example.net \

```

### OpenClaw OTLP Configuration Helpers

Source files:

- `scripts/configure-openclaw-otel.py`
- `scripts/print-otlp-env.py`

Functionality to preserve:

- Basic auth header generation from `node_label:token`.
- Percent-encoded `OTEL_EXPORTER_OTLP_HEADERS` output.
- LAN endpoint selection.
- off-LAN endpoint selection.
- required Cloudflare Access double-auth for off-LAN nodes:
  - `CF-Access-Client-Id`
  - `CF-Access-Client-Secret`
- durable `~/.openclaw/openclaw.json` update behavior.
- timestamped backup before writing OpenClaw config.
- OpenClaw diagnostics settings:
  - `diagnostics.enabled=true`
  - `diagnostics.otel.enabled=true`
  - `diagnostics.otel.protocol=http/protobuf`
  - `diagnostics.otel.logs=true`
  - `diagnostics.otel.captureContent=true`
  - `diagnostics.otel.headers.Authorization`
- avoid setting node/display identity resource attributes client-side; central
  Alloy derives trusted identity from authenticated username.

Required adaptation:

- Remove dependency on central `fleet/nodes.json`.
- Accept endpoint/service/network values explicitly or through a node-local
  config file.
- Keep token material out of git and out of generated docs.

Likely new interface:

```bash
FLEET_INGEST_TOKEN=<token> scripts/configure-openclaw-otel.py \
  --node-label bill \
  --endpoint http://192.168.1.27:4318 \
  --service-name openclaw_gateway

FLEET_INGEST_TOKEN=<token> scripts/print-otlp-env.py \
  --node-label mini_03 \
  --endpoint https://loki-ingest.example.com \
  --service-name openclaw_gateway \
  --cf-access-client-id <client_id> \
  --cf-access-client-secret <client_secret>
```

2. Copy collectors and proxy:
   - `codex-usage-collector.py`
   - `collect-macos-thermal.py`
   - `openclaw-gateway-health.sh`
   - `fleet-node-exporter-proxy.py`
3. Copy collector tests and get them passing.
4. Copy OTLP helpers and remove central inventory dependency.
5. Recreate OTLP helper tests against explicit flags or node-local config.
6. Copy LAN/off-LAN installers and remove central inventory dependency.
7. Recreate installer contract tests.
8. Copy legacy cleanup script.
9. Add install docs and a release compatibility doc.

    this repo instead of requiring the full central checkout on nodes.
